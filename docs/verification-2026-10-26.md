# IEEE 802.11フレーム観測の実機検証（2026-10-26）

記事草稿の「Beacon解析」「フレーム分類」「チャンネル別集計」「RSSI分布」を確認するため、XIAO ESP32C3にESP-IDF 5.5.0のファームウェアを書き込んで測定した。アクセスポイントには接続せず、`WIFI_MODE_NULL`とPromiscuous Modeを使用した。802.11フレームの送信はしていない。

## 条件

| 項目 | 値 |
| --- | --- |
| 観測時間 | 起動後300秒の累積値 |
| 受信チャンネル | 1〜11を順に巡回 |
| 設定滞在時間 | 1チャンネルあたり700 ms |
| 各チャンネルの実観測時間 | 約26.7〜27.6秒（切替・処理時間を含む） |
| 対象 | Management / Control / Dataフレーム |
| 受信処理キューの欠落 | 0件 |

SSIDやMACアドレスを含む生ログは保存していない。識別子を含まない[5分時点の集計出力](../examples/measurement-summary.txt)を保存した。[Beaconの個別行](../examples/serial-output.txt)は、別途観測した値のSSID・BSSIDを置き換え、重複を省略した例である。

## 記事草稿に反映する実装との差分

- 表示例の`[CH]`は現在の`[RX CH] [AP CH]`へ変更する。受信チャンネルは受信メタデータ、広告チャンネルはBeaconのIEから取得する。
- コールバック内でFrame Control・アドレス・BeaconのIEを解析し、結果をキューへ渡す。キューの後段で種類別・チャンネル別の集計とシリアル表示をする。「コールバックではコピーだけ」とは記述しない。
- SSIDは長さ付きバイト列として保持し、表示時に制御文字などをエスケープする。受信バイト列そのものへヌル終端を追加する実装ではない。
- 個別のBeacon行はBSSIDと受信チャンネルの組み合わせにつき最初の1件だけ、最大48行を出す。全受信フレームを1行ずつ出す実装ではない。
- 今回の観測範囲はチャンネル1〜11、設定滞在時間は700 msである。記事の例示値はこの実測条件に置き換える。

## まだ実電波で確認していないこと

- Hidden SSIDのBeaconを実際のAPから受信すること。長さ0のSSIDに対するパーサーのホスト側テストは通した。
- 4アドレスのDataフレームを実際に受信すること。`To DS`と`From DS`がともに1のアドレス対応はホスト側テストで確認した。
- WPA2/WPA3の暗号文を復号すること。今回のプログラムはペイロードを扱わない。
- 電波の全フレーム数や通信量を求めること。チャンネル巡回中の観測漏れ、ドライバ側の取りこぼし、隣接チャンネルでの重複受信はこの集計からは除去できない。

草稿へ転記する際は、観測場所とAP・端末の配置を筆者が確認して追記する。1回の5分測定から、チャンネルの恒常的な混雑度やRSSIと距離の関係を断定しない。
